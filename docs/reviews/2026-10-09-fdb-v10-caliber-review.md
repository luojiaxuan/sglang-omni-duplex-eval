## 采纳情况

- **同意**：主表用上游脚本口径、加门版作诊断，可以成立。
- **反对且改判**：
  1. 不说"与论文数字直接可比"，改称"钉定上游评分脚本、在 SGLang-Omni 原生录制协议下的评分"。录制、ASR 预处理、VAD 和判分模型都可能与论文不同。

  3. 删除"主表可换回加门版"这一回滚条款。按结果切换主表属于事后挑选；改口径必须写明日期和理由，并同时用于所有模型。
  4. 加门版要报样本流转：可评分数、接管数、各道门的计数，以及"接管数 / 全部有效样本"的响应率。否则一个更差的模型可以靠更多样本被门挡掉，反而得到更好的条件指标。
  5. 判分预算改为硬上限的预留账本：每发一次请求前，按"已花费 + 在途预留 + 本次最坏情况"检查不超过 10 美元。正式判分前先离线统计全部请求的 token 数。
- **反对但坚持原判**：它建议正式运行前先跑 52 个 session 的冒烟测试。不采纳：全局规则允许直接发射全量，录制有进度监控和续跑，出错时就地诊断的成本更低。
- **新发现**：上游 v1.0 打断任务的相关性评分写死用 `gpt-4-turbo`，而且有两个 bug：评分解析失败重试时，接管率会被重复计入；成功的评分会被追加两次（均值不变）。照原样运行时要记录重试次数并在报告中写明。

## 原文

1. Concrete divergences

1.1. Pause handling: same takeover rule; different boundary and null handling. Both use elapsed span from first word start to last word end—not summed speech duration—and classify takeover as duration ≥1 s or >3 words. Local scoring first removes words starting at/after T_input, but does not clip retained word ends. Upstream consumes every supplied chunk and substitutes the final word's start when its end is null; the local helper directly subtracts that null. Neither scorer restricts takeover detection to annotated pause intervals. v10_scoring.py:223–248; upstream_eval_pause_handling.py:40–60.

1.2. Turn taking: windowing changes the numerator independently of gates. Upstream computes takeover from the whole supplied transcript, then clamps negative first-word latency to exactly zero. Local scoring first restricts words to [turn_end,T_input), recomputes takeover, and separately excludes VAD-active-at-turn-end samples. Synthetic witness: speech only during [1,2.2], user turn ending at 5 → upstream TOR=1, latency=0; local status=scored, takeover=False. No gate fires in that example. upstream_eval_smooth_turn_taking.py:48,59–80; v10_scoring.py:267–289,303–312.

1.3. User interruption: additional exercise and continuity exclusions. Local scoring assigns not_exercised when VAD is inactive at interruption onset; otherwise assigns talked_through when one segment starts at/before onset and ends strictly after interruption end. Both leave the rate/latency denominator. Upstream checks neither condition; it computes takeover and first-word latency from supplied chunks. v10_scoring.py:326–345,437–450; upstream_eval_user_interruption.py:86–115.

1.4. Critical preprocessing dependency, verified externally at the specified revision: upstream v1_v1.5/get_transcript/asr.py:32–43,59–68 crops interruption audio before Parakeet, then restores absolute timestamps by adding interruption end. Turn-taking ASR is not event-cropped. Therefore, forwarding full-file Parakeet JSON to upstream interruption scoring is wrong; filtering that JSON afterward is also not generally equivalent to cropped-audio ASR. Preserve consistent cropped text and chunks. The attached local configuration instead describes ASR over full output-playout.wav, with post-window words subsequently excluded.

1.5. Backchannel: sample takeover and backchannel membership both differ. For segments ≤3 s, the effective segment takeover predicate is the same: duration ≥1 s or >2 words. But upstream overwrites TOR on each segment and appends every such segment to the backchannel list—even takeover segments. Local scoring ORs takeover across segments and excludes takeover segments from backchannels. Synthetic witness: a 1.2 s segment followed by a 0.4 s acknowledgment → upstream TOR=0, frequency=2/T; local TOR=1, frequency=1/T. upstream_eval_backchannel.py:99–113; v10_scoring.py:358–377.

1.6. Backchannel: early termination, window, and denominator differ. Upstream stops at the first segment strictly longer than 3 s; neither that segment nor later segments enter backchannel timing/frequency. Local scoring continues scanning, ignores segments starting at/after T_input, and clips remaining ends to T_input. Upstream frequency divides by WAV duration; local frequency divides by input duration. Those denominators agree only with correctly bounded exports. upstream_eval_backchannel.py:57–65,113–124; v10_scoring.py:360–377,411.

1.7. Backchannel: word association differs at boundaries/nulls. Local association is word_start < segment_end and word_end > segment_start. Upstream's three branches can include a word starting exactly at segment end; they also explicitly handle/skip null timestamps. Consequently, identical segments and transcripts can cross the two-word threshold differently. upstream_eval_backchannel.py:74–95; v10_scoring.py:366–373.

1.8. Backchannel: VAD execution is not identical. Upstream uses default load_silero_vad(), torchaudio loading/resampling, and return_seconds=True; local uses ONNX, soundfile/scipy resampling, and sample-index timestamps divided by 16 kHz. Under the documented Silero 6.2.1 dependency, upstream defaults mean TorchScript and timestamps rounded to one decimal place. This can change duration thresholds, word association, and bin occupancy even before classifier differences. upstream_eval_backchannel.py:23–44; v10_scoring.py:147–190.

1.9. Backchannel timing formula is otherwise substantially aligned. Given identical accepted segments, duration, and reference: both use 0.2 s inclusive occupancy bins, 1e-10 smoothing, linear reference interpolation, and jensenshannon; both assign 1 for no backchannels. The function returns distance, despite upstream calling it divergence. Upstream requires icc_gt_distribution.json; local permits absent reference and returns None. Upstream reports mean/population standard deviation; local reports count/mean/median/min/max. upstream_eval_backchannel.py:19–21,121–170; v10_scoring.py:210–219,378–412.

1.10. Aggregation differs beyond gates. Local summarization retains selected/missing/status counts, excludes non-scored records, and groups by task—thus pooling the two pause subsets unless invoked separately. Upstream operates on filesystem-discovered samples without that selected-population ledger. Preserve separate synthetic-pause and Candor-pause rows; a pooled pause row is an additional statistic, not their replacement. v10_scoring.py:433–475; README_v10_section.md:6–11; upstream_eval_pause_handling.py:18–26,62–64.

1.11. Interruption relevance is not merely "missing GPT-4o." The attached v1.0 evaluator hardcodes gpt-4-turbo, seed 0, judges only TOR=1 samples, and appends latency only after successfully parsing a rating. Local relevance is absent. Your v1.5 reference judge is gpt-4o-2024-08-06, starting at seed 1. These are different protocols. upstream_eval_user_interruption.py:30–33,114–153; README_v10_section.md:76–77; REFERENCE.md:103–106,150–157.

1.12. Upstream interruption contains consequential execution bugs. take_turn_list.append(TOR) occurs before malformed-rating retry, so eventual completion yields (R+K)/(N+K) rather than R/N, where K is malformed retries. An offline witness confirmed 1/2 → 2/3 after one retry. Each successful rating is appended twice: its mean is unchanged, but its apparent count doubles. Retry is unbounded. The standalone entry point also omits the required client; use the dispatcher or explicit function invocation. upstream_eval_user_interruption.py:67,114–153,170; upstream_evaluate.py:52–60.

1.13. Undefined/error outcomes differ. Upstream turn-taking/interruption divide by empty latency/rating lists; local empty summaries are null-safe. Backchannel's missing-JSON branch does not initialize TOR, allowing an unbound or previous-sample value. Preflight missing artifacts; retain genuine upstream execution failures rather than silently converting them to silence, zero latency, or successful scores. upstream_eval_smooth_turn_taking.py:91–92; upstream_eval_user_interruption.py:159–161; upstream_eval_backchannel.py:49–56,117; v10_scoring.py:210–212.

2. Defensibility and reviewer attacks

2.1. Primary=reference, secondary=behavioral diagnostics is defensible; "directly comparable to published numbers" is too strong. Use "pinned-reference scoring under the SGLang-Omni native capture protocol." Script identity does not establish identical ASR preprocessing, VAD, observation windows, model adapters, dependencies, or judge provenance. Particularly, the pinned upstream README labels v1.0 relevance GPT-4o, while the attached executable requests GPT-4-turbo. That discrepancy must remain explicit; neither label alone establishes how historical published rows were produced.

2.2. Strongest statistical attack: gates remove model-dependent bad outcomes. A worse model can improve conditional latency/rate by generating more excluded samples. For each technically valid population N, report G=scored, R=scored AND takeover, all gate counts, conditional R/G, and explicitly named response yield R/N. For interruption additionally report exercise coverage and talked_through/exercised. Do not classify every not_exercised case as model failure: the test may simply not have interrupted ongoing speech. These diagnostics address the selection induced by v10_scoring.py:326–336,437–450.

2.3. Gate labels are operational proxies, not verified barge-in ground truth. speaking_at includes speech starting exactly at turn end; it misses earlier speech that finished before that boundary and does not distinguish a legitimate short acknowledgment. talked_through requires one continuous VAD segment, not semantic continuation. The censor predicate also flags post-window-only speech when full-playout segments are supplied because it checks only end >= T−0.05. Report these limitations; improve diagnostics under a new version rather than silently changing synthetic-v4. v10_scoring.py:252–253,282–284,303–307,330–336.

2.4. Do not attribute the official/local difference solely to gates. Keep the existing implementation labeled fdb-v10-synthetic-v4 diagnostic. Add a gates-only overlay on reference per-sample outcomes when making causal claims about exclusions; otherwise ASR, windowing, VAD, and backchannel changes are bundled. Display gate counts beside headline latency, not only in an appendix. The source explicitly changes both windows and backchannel membership.

2.5. Freeze the primary analysis; delete outcome-dependent rollback. run_plan.md:24 proposes switching the primary table back by changing aggregation. Replace that with: "Reference-path failure produces an explicitly incomplete reference table; diagnostics remain separately labeled. Any primary-protocol amendment is dated, justified, and applied to both models." Lower latency alone cannot establish superior interruption handling, especially with conditional response populations and pending relevance.
