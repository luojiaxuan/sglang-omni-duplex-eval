# FDB v1.5 一键评测流程：MiniCPM-o，每类 30 对（2026-10-09 起）

## 目的

Chenyang 要求在 H200 上用 sglang-omni#2668 的 v1.5 一键评测流程（`python -m benchmarks.duplex.fdb_v15`），以 `--per-subset 30` 跑一组结果，替换该 PR 文档中样本过小的验证结果（每类 3 对、2 次重复）。`--per-subset 30` 表示四个类别各取样本编号最小的 30 对，共 120 对、240 个会话。

## 决策日志

每条：问题 / 默认 / 理由 / 回滚。

1. **被测模型。** 默认 MiniCPM-o 4.5（`503e754`），服务配置用流程默认的 `examples/full_duplex/minicpmo.yaml`（开启采样）。理由：该流程起服务用 `sglang_omni.cli serve --config`，目前只支持 MiniCPM-o；文档的正式测量也用这个配置。回滚：换模型需新的 `--run-name` 重跑。
2. **重复次数。** 默认 3 次（`--repeat 1..3`），汇总报均值与标准差。理由：与文档中正式测量的写法一致；开启采样后每次结果不同，重复才能估计生成方差。回滚：只用部分重复时，`aggregate` 按已完成的重复汇总。
3. **judge。** 默认流程自带的 `JUDGE=qwen`（Qwen3.8-27B，行为标签与三维度语义判分）。理由：流程默认值；本次是为该 PR 补结果。已知偏差：Nemotron 全量上 Qwen 判"没有有效回应"的比例为 GPT-4o 的约五分之一（见 `2026-10-09-fdb-native-eval.md`），报告时注明。回滚：同一录制可另用 `JUDGE=gpt` 重判。
4. **并行方式。** 每次重复独占一张卡，各自依次录制、转写、判分；不用 `--num-shards`。理由：`--num-shards` 会让两路会话共用一张卡，改变被测延迟（文档原文）；按重复并行不影响测量。回滚：无需。

### 三次重复几乎是同一条采样路径

表中标准差极小（延迟差几毫秒，标签占比最多差 1.9 个百分点）。直接比较三次重复的模型输出转写：120 个 overlap 会话中，82 个（68%）三次逐字相同，第 1、2 次之间 90 个（75%）相同。服务配置开启了采样（`minicpmo.yaml`：`greedy: false`、温度 0.7），录制客户端不传种子，服务端只在请求带 `seed` 或 `sampling_seed` 时才设置种子（`sglang_omni/models/minicpm_o/request_builders.py` 的 `resolve_sampling_seed`）。每次重复各自启动新的服务进程，初始随机状态很可能相同，采样序列于是基本一致，只在计时抖动造成分叉的少数会话上不同。因此文档所说"重复用于估计生成方差"在当前实现下不成立，表中的 ± 远低于真实的生成方差。建议每次重复传入不同的采样种子（例如用重复编号）。
