# 级联音色: 每句都克隆同一段锚点 (2026-10-20)

## 结论

- 级联的音色跳变主要发生在轮与轮之间. 根本原因是每次 TTS 请求都独立采样, 而 CustomVoice 只靠一个说话人 token 维持音色, 锚定太弱.
- 改成 Qwen3-TTS Base, 每句都从同一段 5.4 s Vivian 录音的说话人向量克隆 (不带参考文本) 之后, FDB v1.5 线上口径:
  - 音色一致性 67.3 升到 76.8;
  - UTMOS 4.20 升到 4.52;
  - WER 4.1% 降到 2.7%;
  - 响应延迟 1.06 s 对 1.01 s, 没有变差.
- 带参考文本的 ICL 克隆一致性更高 (79.5), 但每句开头多约 0.4 s 停顿, 响应延迟升到 1.42 s, 所以不用.
- 对应 PR: sgl-project/sglang-omni#3012. 两个英文级联 profile 换成 Base 加锚点, 并改名为 `-vivian`. 私有仓库的 #54 已关闭, 10-20 起不再保密.

## 背景

- 级联把回复按句切开 (遇到句末标点或满 24 词), 每句单独发一次 `/v1/audio/speech`. 10-19 benchmark 用 CustomVoice Vivian, 请求里不带 seed.
- benchmark 的音色一致性是一个跨回复指标: 取每段回复中间 3 s 的 WavLM-ECAPA 向量, 和同一遍其他回复的均值向量算余弦. 级联是 67.3, MiniCPM-o 76.2, Qwen3-Omni 83.6.
- 10-19 级联的 392 段回复里, 265 段 (68%) 只有一次 TTS 请求, 因为系统提示要求一句话回答. 单请求回复和多请求回复的一致性分别是 67.3 和 67.2. 所以句内切分解释不了这个分数, 问题出在跨请求.

## 受控实验

设置: hyper01 一张 H200, 私有 main `3dd888e0`, Qwen3-TTS-12Hz-1.7B 的 CustomVoice 和 Base 两个服务.

- 锚点: CustomVoice Vivian 用 seed 1234 读一句 19 词的英文.
- 样本: 3 个三句回复各重复 6 次, 每个条件 18 段.
- 各列的口径:
  - "句间": 同一回复内三句之间的两两相似度;
  - "跨回复": 不同回复的句子之间的两两相似度;
  - "一致性": benchmark 的留一法;
  - WER 用 Whisper large-v3-turbo 计算.
- 整段请求的分句按词数比例切, 是近似.

| 条件 | 句间 | 跨回复 | 像锚点 | 一致性 | WER % |
| --- | ---: | ---: | ---: | ---: | ---: |
| CustomVoice 逐句 (现状) | 48.2 | 50.1 | 52.1 | 67.8 | 2.38 |
| CustomVoice 整段一次请求 | 59.2 | 51.0 | 51.3 | 71.5 | 2.23 |
| Base 锚点逐句 (本 PR) | 65.2 | 67.5 | 65.3 | 81.3 | 1.93 |
| Base 锚点 + 整段一次请求 | 70.6 | 67.2 | 65.1 | 83.7 | 1.79 |
| Base 句内链式 (以上一句为参考) | 68.0 | 62.2 | 58.7 | 79.9 | 1.79 |
| Base 跨轮链式 | 74.9 | 53.3 | 29.0 | 73.6 | 1.79 |

- 现状条件的一致性是 67.8, 复现了 benchmark 的 67.3.
- 链式克隆会逐渐漂离锚点: 跨轮链式和锚点的相似度只剩 29.0, 因此否决.

- 听感全面变好.
- 响应延迟多了 0.36 s, 四类都在 1.38 到 1.49 s 之间, 说明是普遍现象, 不是个别样本.

- 服务端的 `mask_leading_silence` 只对 x-vector 克隆开启, 在开头 2 帧屏蔽静音码 (#2357), 对 ICL 不起作用.

## 决策记录

- 问题: 修级联音色, 是做"一个回复一次生成" (流式喂文本), 还是给每次请求加锚点?
- 默认答案: 先做锚点, 用 x-vector 克隆. "一次生成"作为后续项.
- 理由:
  - 跨回复指标上, 锚点 +14, "一次生成" +4;
  - 锚点只改配置, "一次生成"要新增把文本追加进在跑 Qwen3-TTS 请求的服务路径;
  - 两者叠加还能再高 2 到 5 分.
- 为什么是 x-vector 而不是 ICL: ICL 的一致性高约 3 分, 但每句开头约 0.4 s 停顿, 让响应延迟多出 0.36 s. 对全双工来说延迟优先.
- 回滚:
  - 改回 ICL: 给两个 profile 加上 `reference_text`, 即 #3012 第二个 commit 的 revert;
  - 改回 CustomVoice: 把 `tts` 改回 CustomVoice 和 `voice: Vivian`, 名字改回 `-customvoice`, 即整个 PR 的 revert.
- 外审: 未能进行. 10-20 21:40 PT 时 Chrome 里的 ChatGPT 是未登录状态, 无法代为登录. 等登录后补审.

## 后续

- 带参考文本的 ICL 克隆高约 3 分一致性. 要用它, 需要像 x-vector 克隆一样屏蔽开头的停顿.

把一个回复做成一次 TTS 生成, 文本边生成边喂进去:

- Qwen3-TTS 的说话模型逐步消费一个待处理文本队列. 队列空、而文本流还没结束时, 它会等待, 这部分和 Qwen3-Omni 共用.
- 缺的是服务端把文本追加进一个在跑请求的路径.
- 受控实验里这一步在锚点之上再加约 5 分句间相似度, 也能降低首包延迟.
