# MiniCPM-o FDB 的 Omni CI 阶段 (2026-10-15 晚, PT)

起因: Chenyang 在群里要求给 MiniCPM-o 加 FDB 的 CI. 规则是申请两张 H100, 能开 DP 2 就开 DP 2, 开不了再开 TP 2; 选一个约 10 分钟跑完的子集作为一个 stage; 校准和 Wenyao 对齐, 新 stage 只需跑约 5 轮.

## 决定

1. **用 DP 2, 不用 TP 2.** MiniCPM-o 单卡显存峰值 33.8 GB (H100 共 80 GB), TP 2 只会多出卡间通信. CI 每个 job 本来就有两张卡. 回滚: 无.
2. **DP 做在 runbook 里, 不走 router.** 给 `generate` 加 `--gpus 0,1`: 每张卡起一个服务, shard i 发给第 i mod N 个服务, 每个服务用自己 GPU 的端口和编译缓存. 配 `--num-shards 2` 时每张卡同时只有一个会话, 计时和主表的单会话口径可比; 同一个服务上开两路则是带负载的计时, 不可比. Rust router 虽然支持转发 `/v1/realtime`, 但测试里还得编译和启动 router, 收益只是多测了一层转发. sglang-omni#2863. 回滚: 关掉 PR, CI 改为单卡单服务.
3. **子集**: v1.5 每类 2 对, v1.0 每子集 5 条. 不跑 judge (`asr` 已经算出 v1.5 计时和 v1.0 统一口径), `JUDGE=gpt` 让 setup 不下载 27B 判分模型. 测试只做协议与覆盖检查, 阈值等校准. sglang-omni#2864 (草稿).
